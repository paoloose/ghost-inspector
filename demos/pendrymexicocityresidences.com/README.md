## Forms

### Inquiry Form (`#inquiry-form`)
Fields:
- First Name (text, required)
- Last Name (text, required)
- Email (email, required)
- Phone (tel, required)
- Postal Code (text, required)

Submit button: **Submit**

On submit:
- Client-side validation (required fields, email format).
- Button shows mini spinner + "Enviando..." text.
- Global overlay does **not** appear for this form (only button-level loading).
- Simulated 200–500ms delay.
- Success message appears below form.
- No actual data is sent.

### Register Form (`#register-form` on `register.html`)
Fields:
- Full Name (text, required)
- Email (email, required)
- Password (password, required, minlength 6)

Submit button: **Register**

On submit:
- Client-side validation.
- Button shows spinner.
- Simulated 200–500ms delay.
- Dummy session stored in `localStorage` under key `rvbr_session`:
  ```json
  {"email":"user@example.com","name":"user","registeredAt":"2026-01-01T00:00:00.000Z"}
  ```
- Success message shown.
- Auto-redirect to homepage after ~1.2 seconds.

Button-level spinners are shown inside:
- Inquiry form submit button
- Register form submit button

The delay is randomized between **200ms and 500ms**.

## Authentication Flow

- If no `rvbr_session` exists in `localStorage`:
  - Header shows "REGISTER" link pointing to `register.html`.
  - Mobile menu shows "REGISTER" item.
- If `rvbr_session` exists:
  - "REGISTER" link is hidden.
  - Header shows "Hola, [name]" greeting + "Logout" button.
  - Mobile menu hides Register and shows Logout.
- Logout clears `localStorage` and reloads the page (with brief global overlay).

## Mobile Responsiveness

- Breakpoints: **980px**, **768px**, **480px**.
- Desktop navigation hides at 980px; hamburger menu appears.
- Two-column layouts stack to single column at 980px.
- Offerings grid: 4 cols → 2 cols (980px) → 1 col (768px).
- Audit panel width adapts at 480px.
- Tap targets are at minimum **44px**.
- Mobile menu slides in from the right.
- `@media (hover: none)` disables hover zoom effects on touch devices.

## Notes / Deviations / Quirks

1. **No PAGE_LOAD logging** — The audit panel only tracks manual interactions, not automatic page-load events.
2. **No actual backend** — All form submissions are simulated client-side with `setTimeout`.
3. **Hotlinked images** — All visual assets load from the original WordPress site. If images are removed or restricted, CSS gradient fallbacks (`img-fallback` class) display in their place.
4. **Typekit fonts omitted** — The original site uses paid Adobe Typekit fonts (Flecha family). The clone uses Open Sans (free, Google Fonts) to preserve a similar clean luxury feel without requiring Typekit authentication.
5. **No video background** — The original site includes a Vimeo background video. The clone uses the hero image slider instead for simplicity and performance.
6. **Gravity Forms omitted** — The original uses Gravity Forms with complex theme logic. The clone uses simple HTML5 forms with custom validation.
7. **No popup overlays** — The original has Divi popups for ownership inquiries. The clone consolidates everything into a single inquiry section.
8. **WhatsApp button added** — The original site had no WhatsApp button. A floating WhatsApp button was added as requested.
9. **Phone number updated** — Original `+1 (424) 453-8669` replaced with `+525543716148` everywhere (footer, tel: links, visible text).
10. **Irrelevant channels removed** — No Telegram, Skype, Facebook Messenger, or other chat widgets are present. Only email, phone, and WhatsApp are kept.
11. **Privacy Policy / Terms links** — These are non-functional (`href="#"`) because the clone does not replicate the policy pages; they show a brief loading state when clicked.
12. **Logo fallback** — If the hotlinked logo fails to load, a text fallback "PENDRY MEXICO" is rendered.
13. **Image `onerror` handlers** — Every `<img>` tag has an `onerror` attribute or a JS listener that applies the `img-fallback` gradient class to the parent container.
